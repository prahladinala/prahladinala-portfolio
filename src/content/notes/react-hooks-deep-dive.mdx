# React Hooks Deep Dive

React Hooks completely revolutionized how we write components. Let's look closely at `useEffect` and `useMemo`.

## The `useEffect` Hook

The most common mistake with `useEffect` is omitting dependencies or recreating them constantly on every render.

```jsx
import { useEffect, useState } from "react";

export function UserProfile({ userId }) {
  const [user, setUser] = useState(null);

  useEffect(() => {
    // Only runs when userId changes!
    fetch(`/api/users/${userId}`)
      .then((res) => res.json())
      .then((data) => setUser(data));
  }, [userId]);

  if (!user) return <div>Loading...</div>;
  return <div>{user.name}</div>;
}
```

## Performance with `useMemo`

If you have a very expensive calculation, you can wrap it in `useMemo` to ensure it only recalculates when its specific dependencies change.

```jsx
const expensiveResult = useMemo(() => {
  return computeExtremelyHeavyTask(data);
}, [data]);
```

> **Pro Tip**: Don't overuse `useMemo`! React is already incredibly fast. Only use it when the calculation actually causes a measurable performance bottleneck.\

## Expandable Deep Dive

<Accordion title="Deep Dive: How does React preserve Hook state between renders?">
React maintains an internal linked list on each Fiber node. The `memoizedState` property points to the first hook, and each hook has a `next` pointer pointing to the following one. On every render, React walks this linked list sequentially. This is why calling hooks conditionally or inside loops violates the Rules of Hooks—React relies exclusively on the exact invocation order to pair each hook call with its preserved state cell!
</Accordion>
